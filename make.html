MAKE YOUR OWN

A GAME OF YOUR OWN, BY HAND OR WITH AN AGENT

Every machine in this arcade is a small Rust program standing on Blip, a kit the games share. Blip looks after the screen, the sound, the coins and the controls; the game keeps its rules and its personality. You can write a game yourself, or describe one to a coding agent such as Claude Code or Codex and build it together, which is how this arcade was made.

► One loop, one canvas

A Blip game is a loop. Each turn it updates the game by the seconds since the last frame, clears a canvas of fixed size, draws, and waits for the next frame. Blip scales the canvas to the window or the phone.

The screens of a game are a list of states with an update and a draw for each. Serpent has four: Title, Play, Dead and Over.

► A robot that plays it

Each game has a bot that plays it through the same controls a person uses, and a list of things it must be able to do. Serpent’s first:

Run a game with BLIP_BOT=1 and the bot plays it and prints a line of results: score, deaths, level, and measures of how much fun the game is. Change one thing, run the same seeds again, and you can see whether the change helped. A tuning number in the code carries a note on why it is what it is; in Serpent, a quick meal raises the score multiple when it comes within 22 steps, “one board width and a turn”.

► By hand

Copy the smallest game that is like yours (Serpent is compact) into crates/<name> and add it to the workspace. Rewrite its main.rs for your rules and its draw.rs, gfx.rs and tunes.rs for its look and sound. Add your game to the list in web/blip_core.js, give it a bot and a playthrough, build it, and play. AGENTS.md in the repository has the full checklist.

Start with one screen, one control and one way to win or lose. Make that fun before adding anything.

► With an agent

Open the repository in Claude Code, Codex or another coding agent. It reads AGENTS.md first, which tells it how the arcade is laid out and what its rules are. Treat it as a teammate: give it a clear brief, point it at a game to learn from, and build in small steps you can play.

Then play it, and ask for one change at a time: a new enemy, a sound, a touch control. When something feels off, ask the agent to measure it with the bot before and after. That is how the games in this cabinet were tuned.

► Play fair with the originals

Make a tribute, not a copy. Write the mechanics and the style from scratch, and never take code, pictures or sound from the original. Its name is a trademark, so give your game a name of its own, as this arcade does: Rally for Pong, Serpent for Snake, Raider for 1942. Then add something the original never had.

► Learn more

docs/blip.md describes the whole Blip kit, and the Blip API page has illustrated examples. Blip is built on Macroquad.

To see how classic games work inside, read Code the Classics (Raspberry Pi Press). It builds games inspired by Pong, Manic Miner and Frogger in Python and explains every decision along the way, with full source code. A second volume followed.
